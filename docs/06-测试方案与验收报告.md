# Tianci OA 测试方案与验收报告

> 版本：V1.0  
> 范围：`Tianci-OA-Api`、`Tianci-OA-Web`、MySQL 初始化脚本与 Docker Compose  
> 原则：测试结果严格区分“通过、失败、未执行”，未连接真实 MySQL/Redis 的场景不记为通过。

## 1. 测试目标

- 验证登录、RBAC、员工、招聘、多轮面试、入职、合同、文件和工作流主流程。
- 验证前后端契约、状态机、雪花 ID、统一响应、异常与并发控制。
- 验证数据库结构、安全边界与 10 万员工规模下的性能设计。
- 为部署环境的完整集成、性能与安全测试提供可重复的用例和验收标准。

## 2. 测试范围与策略

| 层级 | 内容 | 方法 |

| 静态检查 | 代码占位、路由、配置、SQL 结构 | 搜索、人工审查、Compose 解析 |

## 3. 测试环境与数据

### 3.1 建议环境

- .NET SDK 10.0.x；
- Node.js 20+、pnpm；
- MySQL 8.0，`utf8mb4_0900_ai_ci`，UTC；
- Redis 7；
- Docker 29+ / Docker Compose；
- Chrome、Edge 最新两个稳定版本。

### 3.2 角色数据

| 账号 | 角色 | 数据范围 |
| --- | --- | --- |
| `admin` | 超级管理员 | 全部 |
| `hr_a` | 人事专员 | 全部 |
| `manager_a` | 部门负责人 | 本部门及下级 |
| `interviewer_a` | 面试官 | 本人被安排 |
| `employee_a` | 普通员工 | 仅本人 |
| `disabled_user` | 任意 | 停用 |

开发默认管理员可直接登录，但必须在首次登录后修改密码；共享和生产环境不得保留默认凭据。

### 3.3 业务数据

- 至少 3 个部门及父子层级、6 个岗位；
- 30 名员工，覆盖试用、在职、离职、归档；
- 20 份简历，覆盖待筛选、面试中、待录用、待入职、淘汰、已入职；
- 1～5 轮面试记录；
- 合同覆盖草稿、生效、临期、到期、终止、归档；
- PDF、DOCX、JPG、PNG 合法文件以及 EXE、双扩展名、伪造文件头、超大文件。

## 5. API 测试

每个接口检查：

- 请求：必填、长度、枚举边界、日期、雪花 ID 字符串、分页最大值；
- 响应：HTTP 状态、`success/code/message/data/traceId`、分页结构；
- 认证：缺 Token、过期 Token、伪造签名、停用用户；
- 授权：缺功能权限、越数据范围、缺敏感字段/文件权限；
- 异常：不存在、重复编号、非法状态、旧版本号、重复请求；
- 审计：关键成功/失败动作与 TraceId 可追溯。

重点接口：

| 接口 | 正常断言 | 异常断言 |
| --- | --- | --- |
| `POST /api/v1/auth/login` | 返回 Token/权限 | 错误密码、停用用户、限流 |
| `GET /api/v1/employees` | 分页与数据范围正确 | 超大 pageSize 被限制 |
| `POST /api/v1/resumes/{id}/interviews` | 生成合法轮次 | 轮次 > 5、状态不允许 |
| `POST /api/v1/resumes/{id}/confirm-entry` | 原子创建员工 | 重复确认、材料缺失回滚 |
| `POST /api/v1/contracts/{id}/activate` | 正确生效 | 无附件、旧版本号 |
| `POST /api/v1/files` | 合法文件成功 | 类型、文件头、大小、路径攻击 |
| `POST /api/v1/workflows/{instanceId}/nodes/{nodeId}/decision` | 推进节点 | 非审批人、重复 requestId、并发冲突 |

## 6. 数据库测试

### 6.1 结构

- 17 张核心表均存在；
- 所有业务主键为 `bigint unsigned`，无 `AUTO_INCREMENT`；
- 字符集/排序规则正确；
- 外键、唯一索引、复合索引与脚本一致；
- `created_at/by`、`updated_at/by`、逻辑删除字段规范一致；
- 开发默认管理员可登录；修改密码后重复执行脚本不重置密码。

### 6.2 完整性与事务

- 唯一用户名、员工编号、候选人编号、合同编号重复时失败；
- 非法外键、面试轮次、评分、合同日期违反约束时失败；
- 确认入职中任一步失败时，员工、入职、流程、附件关联全部回滚；
- 乐观锁冲突影响行数为 0 并映射 409；
- 逻辑删除数据不出现在普通查询；
- 审计日志和流程记录为只追加。

### 6.3 索引验证

在 10 万员工数据集上执行 `EXPLAIN ANALYZE`：

- 员工部门/状态/更新时间分页；
- 姓名、员工编号、手机号前缀搜索；
- 候选人状态/岗位看板；
- 合同状态/结束日期提醒；
- 操作日志按对象和时间查询。

不得出现无界全表返回；若执行计划未使用预期索引，应作为上线阻塞问题处理。

## 8. 性能测试

### 8.1 数据规模

- 员工 100,000；
- 候选人 200,000；
- 面试记录 400,000；
- 合同 150,000；
- 操作日志 2,000,000。

### 8.2 场景与目标

| 场景 | 负载 | 验收目标 |
| --- | --- | --- |
| 并发登录 | 100 虚拟用户，持续 5 分钟 | P95 < 1 秒，错误率 < 1% |
| 员工列表 | 200 并发，分页/筛选 | P95 < 2 秒，错误率 < 1% |
| 招聘看板 | 100 并发 | P95 < 2 秒 |
| 合同到期查询 | 100 并发 | P95 < 2 秒 |
| 面试提交 | 50 并发，含同记录冲突 | 无重复推进，冲突返回 409 |
| Dashboard | 100 并发 | P95 < 2 秒，单区失败不拖垮 API |

同时监控 API CPU/内存/GC、连接池、Redis 命中率、MySQL QPS/锁/慢查询。测试结束后数据一致、无连接泄漏和不可恢复错误。

## 11. 验收结论

当前代码基线满足“设计文档齐备、前后端可构建、核心模块完整、关键领域单元测试通过、API 可启动、部署配置可解析”的开发交付条件。

由于真实 MySQL/Redis 端到端联调、角色越权矩阵、文件端到端、性能和渗透测试尚未执行，本报告结论为：

**开发验收通过；生产发布验收待环境集成测试。**

生产发布前必须全部满足：

1. 空库初始化与重复初始化通过；
2. 招聘—多轮面试—录用—入职—合同—归档主流程通过；
3. 超级管理员、HR、部门负责人、面试官、普通员工的权限矩阵通过；
4. SQL 注入、水平/垂直越权、文件上传安全无高危缺陷；
5. 10 万员工规模关键接口达到第 8 节目标；
6. 无 P0/P1 缺陷，P2 缺陷具有接受人和修复计划。
